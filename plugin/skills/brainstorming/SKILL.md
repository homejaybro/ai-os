# 設計對話 — 設計對話（少問、多自己判斷）

目標：把模糊的想法變成每個功能一份規格，再加一頁讓使用者說一次「好」的決策總表。已在核准清單內的功能不走這個流程。

## 提問預算

1. **有上限**：開案最多 7 題；之後每個階段最多 5 題。用完就不再問，剩下的缺口選推薦做法，寫進決策總表「我替你決定的事」。使用者說「你全部決定」→ 不問，直接出總表。
2. **只問只有使用者能回答的**：做什麼、給誰用、這次不做什麼；風格、用語、品牌感；花錢、申請外部帳號、真實世界資訊（GitHub 倉庫網址、要不要收款）。
3. **其餘自己決定**：技術選擇（採推薦棧）、失敗與備援、邊界情況、誤用、半途中斷、空狀態、未來擴充、命名、檔案放哪、怎麼測。事實性的東西先用工具查（讀檔、CodeGraph、網路）。
4. **問的方式**：一次一題、白話、附建議答案，使用者回「好」即可。
5. **紅線預先核准**（登入做法、資料存取規則、資料表）不另外問：你提建議，放進決策總表第 4 區讓使用者一次點頭。

## 流程

1. **理解脈絡**：讀 `_管理/常駐/專案規格.md`（STACK_RULES）、`方案紀錄.md`、`領域詞彙.md`（對話中用這裡的詞）、相關的 `_管理/specs/`。
2. **提問（遵守預算）＋自己補盲點**：誤用、未驗證的假設、空資料與極端值、半途中斷（離開、斷網、重複送出），逐項寫出預設處理方式，不問使用者。
3. **技術選擇**：偏離推薦棧或使用者有疑慮才呈現選項（格式見 `ai-os:tech-choice` 技能），其餘自己選，記入 `方案紀錄.md`。
4. **每個功能寫一份規格**：`_管理/specs/{功能名}.md`，格式見 `${CLAUDE_PLUGIN_ROOT}/templates/forms/功能規格範本.md`。上半是設計（你會看到什麼、範圍、做法、邊界情況、需要點頭的紅線），下半是可逐條勾選的驗收條件。核准前就備好，核准後才不用回頭問。
5. **送審（視情況）**：這個階段有 3 個以上功能，或涉及紅線 → 派一次 `ai-os:reviewer`（模式二：設計文件審查），一次審完全部規格。它的發現你自己補進規格；只有會改變產品意圖的才問使用者（算進提問預算）。
6. **決策總表**：照 `${CLAUDE_PLUGIN_ROOT}/templates/forms/決策總表範本.md` 呈現一頁白話總表（一個階段的多個功能合成一張）。使用者說「好」→ 把核准內容記入 `此次任務.md` 的核准欄與 `方案紀錄.md`，之後一路做到完成（**開案時例外**：先照 `_管理/開案確認.md` 的初始化步驟做完、請使用者重開，才開始寫功能）。使用者有不同意見 → 修正後再呈現。

## 注意

- 決策在主對話做，不交給子 Agent。
- 討論中出現需要解釋兩次以上的概念 → 收斂成一個詞補進 `領域詞彙.md`。
- 判定是大型任務（見 `ai-os:big-task` 技能 開頭）→ 接著照該技能拆成垂直切片。
