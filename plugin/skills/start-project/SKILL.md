# 開案（ai-os 新專案）

目標：把想法收斂成第一階段的規格與一頁決策總表，使用者說一次「好」之後把專案建好。

## 0. 先判斷這是哪種資料夾

- `_管理/常駐/此次任務.md` 存在、「當前步驟」有內容 → 已開過案，不走這裡，照共用規則「啟動」接續。
- `_管理/常駐/此次任務.md` 存在、「當前步驟」是空的 → 開案做到一半：看 `_管理/開案確認.md` 與 `_管理/specs/` 已填到哪，從那一步接續。
- 已有程式碼或其他專案檔（`.git`、`.claude/` 以外）→ 不是新案。告訴使用者這套開案流程只用於新專案，既有專案要先探索、再規劃。不複製任何檔案。
- 空資料夾 → 從第 1 步開始。

## 1. 建骨架、載入共用規則

1. 複製專案骨架（不覆蓋已存在的檔）：
   ```bash
   cp -rn "${CLAUDE_PLUGIN_ROOT}/templates/project/." .
   ```
2. 讀完 `${CLAUDE_PLUGIN_ROOT}/rules.md` 全文，這個對話接下來照它做（共用規則要到下次開對話才會自動載入）。

## 2. 討論與規格

照 `ai-os:brainstorming` 進行。第一階段的每個功能各寫一份 `_管理/specs/{功能名}.md`。

## 3. 決策總表

內部填好 `_管理/開案確認.md`（使用者不用讀），再照 `${CLAUDE_PLUGIN_ROOT}/templates/forms/決策總表範本.md` 呈現，請使用者說一次「好」。有不同意見就修正後再呈現。

## 4. 初始化

使用者說「好」之後，照 `_管理/開案確認.md` 最後的「初始化執行步驟」逐步做完。先初始化，不要直接開始寫功能。

## 5. 請使用者重開

告訴使用者（一次一步）：
1. 把 Claude Code 關掉再開這個資料夾。
2. 第一次在這個資料夾開新對話時，會出現「此工作區未受信任」提示：照常送出訊息，跳出詢問時選「信任工作區」。
3. 輸入 `/mcp`，確認 codegraph（和這次追加的 MCP）都在清單裡。
4. 回一句「重開了」，就從第一個功能開始做。
