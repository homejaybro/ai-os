# 開案（ai-os 新專案）

目標：把想法收斂成第一版的規格與一頁決策總表，使用者說一次「好」之後把專案建好。

## 0. 先判斷這是哪種資料夾

- `_管理/常駐/此次任務.md` 存在、專案階段的「開案」已打勾 → 已開過案，不走這裡，照共用規則「啟動」接續。
- `_管理/常駐/此次任務.md` 存在、「開案」沒打勾 → 開案做到一半：「當前步驟」寫了初始化第幾步就從那步接續；沒寫就看 `_管理/開案確認.md` 與 `_管理/specs/` 已填到哪。
- 已有程式碼或其他專案檔（`.git`、`.claude/` 以外）→ 不是新案，不複製任何檔案。告訴使用者這套開案流程只用於新專案；要交給 ai-os 管就輸入 `/ai-os:adopt`（同意後也可由你讀 `${CLAUDE_PLUGIN_ROOT}/skills/adopt/SKILL.md` 照做，檔內的 `${CLAUDE_PLUGIN_ROOT}` 換成外掛的實際路徑）。
- 空資料夾 → 從第 1 步開始。

## 1. 環境檢查、建骨架、載入共用規則

1. 照 `ai-os:env-setup` 第〇節「檢查與安裝」做完；要重開就停在這裡，重開後從第 0 步再判斷。
2. 複製專案骨架（不覆蓋已存在的檔）：
   ```bash
   cp -rn "${CLAUDE_PLUGIN_ROOT}/templates/project/." .
   ```
3. 讀完 `${CLAUDE_PLUGIN_ROOT}/rules.md` 全文，這個對話接下來照它做（共用規則要到下次開對話才會自動載入）。

## 2. 討論與規格

照 `ai-os:brainstorming` 流程做到第 6 步（草圖）。第一版的每個功能各寫一份 `_管理/specs/{功能名}.md`。

## 3. 決策總表

內部填好 `_管理/開案確認.md`（使用者不用讀），再照 `ai-os:brainstorming` 第 7 步呈現總表。

## 4. 初始化

使用者說「好」之後，照 `_管理/開案確認.md` 最後的「初始化執行步驟」逐步做完。先初始化，不要直接開始寫功能。

## 5. 請使用者重開

告訴使用者（一次一步）：
1. 把 Claude Code 關掉再開這個資料夾。
2. 第一次在這個資料夾開新對話時，會出現「此工作區未受信任」提示：照常送出訊息，跳出詢問時選「信任工作區」。
3. 回一句「重開了」。你自己確認 codegraph（和這次追加的 MCP）的工具都在；看不到才請使用者輸入 `/mcp` 檢查，再從第一個功能開始做。
