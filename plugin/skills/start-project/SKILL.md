# 開案（ai-os 新專案）

使用者非工程背景。開案的目標：把模糊想法收斂成第一階段的規格與一頁決策總表，使用者說一次「好」之後把專案建好。

## 0. 先判斷這是哪種資料夾

- `_管理/常駐/此次任務.md` 存在、「當前步驟」有內容 → 已經開過案，不走這裡，照共用規則「啟動」接續。
- `_管理/常駐/此次任務.md` 存在、「當前步驟」是空的 → 開案做到一半：看 `_管理/開案確認.md` 與 `_管理/specs/` 已經填到哪，從那一步接續。
- 資料夾裡已經有程式碼或其他專案檔（`.git`、`.claude/` 以外）→ 這不是新案。告訴使用者：這套開案流程只用於新專案；既有專案要另外先探索、再規劃。不要複製任何檔案。
- 空資料夾 → 從第 1 步開始。

## 1. 建骨架、載入共用規則

1. 把專案骨架複製進來（不覆蓋已存在的檔）：
   ```bash
   cp -rn "${CLAUDE_PLUGIN_ROOT}/templates/project/." .
   ```
   會得到：`CLAUDE.md`（只有一行 `@~/ai-os/plugin/rules.md` 載入共用規則）、`_管理/常駐/` 四個常駐檔、`_管理/開案確認.md`、`_管理/specs/`、`_產出/`、`_開發檔案/tests/e2e/`、`.gitignore`、`.mcp.json`、`playwright.config.ts`、`.github/workflows/test.yml`、`.claude/settings.json`。
2. **讀完 `${CLAUDE_PLUGIN_ROOT}/rules.md` 全文**，這個對話接下來照它做。剛建立的 `CLAUDE.md` 要等重開 Claude Code 才會自動載入，所以這次要自己讀。

## 2. 討論與規格

照 `ai-os:brainstorming` 技能進行（開案最多 7 題，每題附建議；其餘自己判斷）。第一階段的每個功能各寫一份 `_管理/specs/{功能名}.md`。

## 3. 決策總表

內部填好 `_管理/開案確認.md`（使用者不用讀），再照 `${CLAUDE_PLUGIN_ROOT}/templates/forms/決策總表範本.md` 呈現一頁白話總表，請使用者說一次「好」。有不同意見就修正後再呈現。

## 4. 初始化

使用者說「好」之後，照 `_管理/開案確認.md` 最後的「初始化執行步驟」逐步做完（填常駐檔、git init、建專案、MCP、CodeGraph、測試設定、首次 commit、推送、打標籤）。**先初始化，不要直接開始寫功能。**

## 5. 請使用者重開

告訴使用者（一次一步）：
1. 把 Claude Code 關掉再開這個資料夾。
2. 會跳出「允許讀取外部檔案」的確認框——這是專案要載入 ai-os 共用規則，請選允許。選了不允許的話，共用規則不會生效。
3. 輸入 `/mcp`，確認 codegraph（和這次追加的 MCP）都在清單裡。
4. 回一句「重開了」，就從第一個功能開始做。
