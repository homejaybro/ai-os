# 大型任務與退回版本

## 一、大型任務

什麼算大型：一件事要改很多檔（大約 15 個以上），或預期一個對話做不完、要分好幾次接續。檔案多但很機械（例如全部改名）不算。

### 做法

1. 開分支並記下起點（最後審查要用）：
   ```bash
   git checkout -b feat/{英文短名}
   git rev-parse HEAD
   ```
2. 拆成垂直切片：每一片是一條「窄但完整」的路徑（資料表＋邏輯＋畫面＋測試），做完使用者就能點開確認。不要先做完全部資料表、再做全部畫面。
   - 例外：改名、改介面這類橫跨大量呼叫點的機械式改動，分三段做——先讓新舊並存 → 分批改呼叫點 → 最後移除舊的，每段做完系統都還能跑。
3. 寫 `_管理/任務分解.md`（格式見 `${CLAUDE_PLUGIN_ROOT}/templates/forms/任務分解範本.md`）：切片清單、順序、每片的驗收標準，並逐條對照規格確認沒有漏掉的需求。在 `此次任務.md` 的「當前步驟」寫「大型任務進行中，見 `_管理/任務分解.md`」。
4. 一片一片做：用內建的待辦清單追蹤，每片照共用規則「驗證」的等級驗證，在 `任務分解.md` 打勾、記下驗證結果，再連同程式碼一起 commit。互不相干的切片可以派子 Agent 同時做（兩者不能改同一批檔）。
5. 全部做完後審查整個分支：照 `ai-os:delegate`「派 reviewer 前」準備材料（diff 起點用步驟 1 記下的 hash），派 `ai-os:reviewer` 或用 `/code-review`。
6. 收尾：
   ```bash
   git checkout main
   git merge --no-ff feat/{英文短名}
   git push
   git branch -d feat/{英文短名}
   ```
   是該階段最後一件事才打里程碑標籤、在 `此次任務.md` 的「專案階段」打勾。向使用者說明成果時，只列「每片做完使用者能做什麼」，不貼整份計畫。

## 二、退回與保護現場

### 改到一半失敗

先保護現場，不要直接重跑：
```bash
git status
git stash
```
- 繼續：修正後 `git stash pop` 恢復
- 重來：stash 留著不刪，從乾淨狀態重做
- 不確定：保留 stash，問使用者

### 退回到某一版（使用者說「回到某某那版」）

1. 先打備份標籤：`git tag backup-YYYYMMDD-HHMM`
2. 把工作區還原成目標版的內容：`git rm -r -q .`（只清已追蹤的檔）→ `git checkout <目標版的標籤或 hash> -- .`；再把管理文件與規則還原成現況：`git checkout backup-YYYYMMDD-HHMM -- _管理 CLAUDE.md .claude _開發檔案/scripts`（否則決策、踩坑、核准欄會一起退掉）。在 `此次任務.md` 記一句「已退回到 {版本}」，並在 `方案紀錄.md` 脈絡區追加原因
3. 含程式碼就先跑 STACK_RULES 的驗證指令，再 commit 成一筆「還原到 {版本白話名}」，然後 `git push`
4. 退錯了：用同樣步驟退回 `backup-…` 標籤

不用 `git reset --hard`（會抹掉歷史），也不用整段 `git revert`（遇到合併紀錄會報錯）。只撤銷單一個 commit 時才用 `git revert <hash>`（合併紀錄要加 `-m 1`）。

### 已部署的版本要回滾

屬紅線（正式環境），先問使用者。用平台自己的回滾機制（Vercel Deployments、資料庫時間點還原等），不靠 git——`git revert` 不會撤回已發生的部署與資料變更。
