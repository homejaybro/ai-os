# 方案紀錄 — 已定案決策 + 討論脈絡 + 踩坑

> 本專案「做過哪些決定、為什麼、踩過哪些坑」的唯一來源（git log 記做了什麼，這裡記為什麼）。
> 一個決策兩區各記一次：速查表一行（結論），脈絡區一則（原因）；速查表的「脈絡」欄指向脈絡區的日期標題。

| 區塊 | 何時讀 | 寫入規則 |
|---|---|---|
| 一、已定案決策速查表 | 寫程式前掃一遍，確認不違反已定案 | 追加列；決策被取代時只改「狀態」欄（`生效` → `已被 #N 取代`），不刪列 |
| 二、討論脈絡 | 需要回顧「當初為什麼」時 | 只追加，不修改既有條目 |
| 三、踩坑 | 寫程式前讀 | 追加；依主題分區 |

## 三、踩坑

> 寫入時機：踩到「下次還會再踩、而且從程式碼或文件讀不出來」的坑時當次寫（含子 Agent 回報的坑）。通用的 CRUD 注意事項見 `ai-os:crud-tests`，不抄在這裡。
