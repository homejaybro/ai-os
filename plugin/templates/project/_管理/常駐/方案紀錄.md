# 方案紀錄 — 已定案決策 + 討論脈絡 + 踩坑

> 本檔是「本專案做過哪些決定、為什麼、踩過哪些坑」的**單一來源**。
> git log 記「做了什麼」，這裡記「為什麼這樣規劃」；兩者互補，不重複。

**三個區塊，各有用途：**

| 區塊 | 是什麼 | 誰讀 | 寫入規則 |
|---|---|---|---|
| **一、已定案決策速查表**（下方）| 結論的一行速查——技術選型、schema、UI 規範、部署、其他架構決策 | 寫程式前掃一遍，確認實作方向不違反已定案 | 追加列；決策被取代時只改「狀態」欄（`生效` → `已被 #N 取代`），不刪列 |
| **二、討論脈絡**（速查表之後）| 每個決策的完整背景：考慮過的選項、為何選它、排除原因、影響範圍 | 主 Agent 需要回顧「當初為什麼」時按需讀 | 只追加，不修改既有條目 |
| **三、踩坑**（檔案最後）| 本專案「下次還會再踩」的坑：標題＋根因＋修法 | 寫程式前讀 | 追加；依主題分區 |

> 一個決策**兩區塊各記一次**：速查表一行（結論），脈絡區一則（原因）。速查表的「脈絡」欄指向脈絡區的日期標題。

## 二、討論脈絡

> 格式：`### [YYYY-MM-DD] {討論主題}`，每則含：
> - **討論背景**：為什麼要討論這個
> - **考慮的選項**：列出評估過的方案
> - **決策結果**：選擇了什麼、原因是什麼
> - **排除原因**：其他選項為何不採用
> - **影響範圍**：哪些功能或後續步驟需要配合這個決策

（尚無記錄）

---

## 三、踩坑

> **寫入觸發點**：踩到「下次還會再踩」的坑時當次寫（含子 Agent 回報的坑）。
> 判準：這個坑「存在於程式碼或文件裡、下個 fresh session 讀得到嗎？」否 → 寫這裡。
> 通用的 CRUD／前端注意事項見 `ai-os:crud-tests` 技能與 CoreBrain wiki，不重複抄在這裡。

每條：標題＋根因＋修法，依主題分區（如 Auth／Create／Read／Update／Delete／上傳／跨操作／UI）：

```
**A-1：（簡短標題）**
- 根因：……
- 修法：……
```
