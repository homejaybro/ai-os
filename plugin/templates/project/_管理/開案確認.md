## 初始化執行步驟（使用者說「好」後，主 Agent 依序執行）

> 以下是主 Agent 的執行清單，使用者只要對決策總表說「好」即可。先讀 `ai-os:env-setup` 技能的第一、二節，本步驟依它執行。

1. **填入所有常駐檔**：`CLAUDE.md` 第一行的 `{專案名稱}`、STACK_RULES、領域詞彙初始詞條；`此次任務.md` 的「專案階段」（照上方確認的階段填入，並勾「開案」）與「目前核准的階段與功能」欄照上方填入；**決策寫入 `方案紀錄.md`**（確認版技術棧表每一列與預先核准事項帶入速查表，脈絡區補選型原因）；**`此次任務.md` 的「當前步驟」填入第一步**（否則重開後會被誤判成還沒開案）
2. `git init -b main`（資料夾已經有 `.git` 且有 commit，代表這個專案已開過案，**不要重建**，改成接續上次）
3. 依上方確認的目錄結構建立專案（框架腳手架指令依 STACK_RULES；腳手架一律加 `--no-git`。工具若拒絕非空資料夾，就在暫存資料夾建好再把檔案搬進來，不可覆寫 `.gitignore`、`CLAUDE.md`）
4. **依 STACK_RULES 追加需要的 MCP 到 `.mcp.json`**（清單見 `ai-os:env-setup` 第二節）
5. `codegraph init -i` 建立依賴索引
6. **補好測試與 CI 設定**：`playwright.config.ts` 的 `webServer`（依 STACK_RULES 的開發指令與埠號）、`.github/workflows/test.yml` 需要的環境變數（用測試假值）
7. **確認 `.gitignore` 已涵蓋機密**（`git status` 檢查 `.env*`／`_secrets/` 未被追蹤）；先跑驗證（STACK_RULES 的 build／型別檢查；`playwright.config.ts` 算程式碼，首次 commit 一定需要一次驗證紀錄），再依 `ai-os:env-setup` 的「應 commit 清單」執行首次 commit，訊息寫「建立專案骨架（AI OS）」
8. 有填 GitHub 倉庫網址 → `git remote add origin <網址>`、`git push -u origin main`；打標籤 `git tag -a milestone-YYYYMMDD-init -m "開案完成"` 並 `git push --tags`
9. **請使用者重開 Claude Code**。第一次開新對話會出現「此工作區未受信任」，請他送出訊息時選「信任工作區」；再輸入 `/mcp` 確認 codegraph 與本次追加的 MCP 都已載入——**確認後才進入第一個功能**（MCP 與 CodeGraph 索引只在啟動時載入）
