## 初始化執行步驟（使用者說「好」後依序執行）

> 先讀 `ai-os:env-setup` 第一、二節。每做完一步，把 `此次任務.md` 的「當前步驟」更新成「開案初始化：做完第 N 步」（中途斷掉時新對話從這裡接續）。

1. 填入常駐檔：`CLAUDE.md` 第一行的 `{專案名稱}`；STACK_RULES（含上方技術棧、目錄結構）；領域詞彙初始詞條；`此次任務.md` 的「專案階段」（照上方填入，「開案」先不勾）與「核准清單」；`方案紀錄.md`（確認版技術棧表每一列與預先核准事項帶入速查表，脈絡區補選型原因）
2. `git init -b main`（已經有 `.git` 且有 commit → 不要重建，從「當前步驟」記的那步接續）
3. 依上方目錄結構建立專案（腳手架指令依 STACK_RULES，一律加 `--no-git`。工具拒絕非空資料夾時，在暫存資料夾建好再搬進來，不可覆寫 `.gitignore`、`CLAUDE.md`）
4. 依 STACK_RULES 追加需要的 MCP 到 `.mcp.json`
5. `codegraph init -i` 建立依賴索引
6. 測試與自動測試設定：網站專案補好 `playwright.config.ts` 的 `webServer`（依 STACK_RULES 的開發指令與埠號）與 `.github/workflows/test.yml` 需要的環境變數（用測試假值）。不是網站或不是 Node 專案 → 刪掉 `playwright.config.ts` 與 `_開發檔案/tests/e2e/`，`test.yml` 改成該技術棧的驗證指令，沒有就刪掉。專案沒有存檔把關認得的驗證指令（例如純 HTML、腳本工具）→ 建一個 `package.json` 的 `test` 腳本做語法檢查，寫進 STACK_RULES 的開發指令
7. `git status` 確認 `.env*`／`_secrets/` 未被追蹤；先跑 STACK_RULES 的 build／型別檢查，再照 `ai-os:env-setup` 第一節的清單做首次 commit，訊息寫「建立專案骨架（AI OS）」
8. 打標籤 `git tag -a milestone-YYYYMMDD-init -m "開案完成"`。有 GitHub 倉庫網址 → `git remote add origin <網址>`、`git push -u origin main`、`git push --tags`
9. `此次任務.md` 勾「開案」，「當前步驟」寫「重開後先確認 codegraph 與追加的 MCP 工具都在，再做：{第一步的第 1 個任務}」，commit 並推送
10. 請使用者重開 Claude Code（步驟見 `ai-os:start-project` 第 5 步）
