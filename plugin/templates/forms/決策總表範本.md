# 決策總表範本

> ⚠️ 空白格式範本。討論階段結束時，主 Agent 用這個格式向使用者呈現**一頁白話總表**（不超過一頁、不出現技術用語），請他說一次「好」。
> 開案時，`_管理/開案確認.md` 由主 Agent 內部填寫，給使用者看的是這張總表。核准後的內容記入 `此次任務.md` 的核准欄與 `方案紀錄.md`。

```markdown
# 決策總表：{專案或階段名稱}

## 1. 我們要做什麼、不做什麼
- 要做：（一兩句）
- 這次不做：（一兩句）

## 2. 這一階段的功能（做完你會看到什麼）
1. {功能名}：（一句話，你／使用者視角）
2. …

## 3. 我替你決定的事（掃過即可，不同意再說）
- 技術選擇：{採用推薦做法}——（一句好處）
- 遇到問題時怎麼處理：（例：網路斷線時會提示「請稍後再試」，不會弄丟你填的資料）
- 其他小決定：…

## 4. 需要你點頭的事
- 登入／權限做法：…
- 資料存取規則（誰能看、改哪些資料）：…
- 會建立或修改的資料：…
- 備份上傳：GitHub 倉庫網址（沒有可先跳過）

## 5. 之後仍會再問你的事（做之前一定再確認一次）
正式環境上線或改資料、真實扣款、刪除欄位或資料表、要換掉已決定的技術

---
請回覆「好」開始；有不同意的項目，直接告訴我是哪一項。
```
