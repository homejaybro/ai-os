# 功能規格範本

> 空白格式範本。每個功能在 `_管理/specs/` 建一份 `{功能名}.md`（如 `auth.md`），複製下方骨架填寫。
> 一份就夠：上半是設計（給使用者對焦、給實作的人理解），下半「驗收條件」是完成標準與測試依據。測試腳本對應檔名：`auth.md` → `auth.spec.ts`。

```markdown
# {功能名稱}

## 做完你會看到什麼
<!-- 白話、用「你／使用者」視角，2–4 句，不出現檔名、型別、API、資料庫這些詞 -->
（例：你在料卡列表頁按「批次匯入」，選一個 Excel 上傳。系統會比對現有料卡，
 分成「要新增的／要修改的／有衝突的」三區給你看；你勾選要匯入的，按確認才會寫進系統。）

## 範圍
- 這次包含：
- 這次不包含：

## 驗收條件
<!-- 每條寫「使用者做 X → 系統回應 Y」，非技術者也讀得懂 -->
- [ ]（正常流程）使用者執行 X → 系統回應 Y
- [ ]（錯誤情況）輸入 Z → 顯示錯誤訊息 W
- [ ]（邊界情況）沒有資料／資料量很大／有重複值 → …
- [ ]（半途中斷）做到一半離開／重複送出 → …

## 需要點頭的紅線（沒有就寫「無」）
（登入／權限做法、資料存取規則、要建立或修改的資料表，白話寫）

## 🔧 開發區（非技術者可略過）

### 做法
（實作方式、主要流程、可能連帶影響的功能）

### 邊界情況與備援
（失敗、誤用、空狀態、半途中斷的預設處理）

### 頁面／元件、欄位
| 欄位名 | 型別 | 必填 | 說明 |
|---|---|---|---|
| | | | |

### 對應測試腳本
`_開發檔案/tests/e2e/{功能名}.spec.ts`
```
